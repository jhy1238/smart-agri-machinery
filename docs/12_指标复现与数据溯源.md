# 指标复现与数据溯源

本文件回答一个问题：**README 和作业报告里的每个数字，凭什么可以信、怎么自己复现？**

三条原则：

1. **一个数字一条命令**：所有指标由 `node src/cli.mjs` 一次跑出，写入 `data/run_report.txt` 与 `data/run_result.json`；
2. **一个数字一条断言**：`node src/selftest.mjs` 用 103 项数值断言守住这些指标，断言失败即非零退出（CI 强制）；
3. **一个数字一个出处**：每个指标指明生成它的源文件，便于追到算法实现。

---

## 1. 复现环境

| 项目 | 值 |
|---|---|
| 运行时 | Node.js ≥ 18（入库产物由 v24.19.0 生成） |
| 依赖 | 无（零第三方依赖，无需 `npm install`） |
| 随机种子 | 默认 20240501（`--seed=<n>` 可换场景，指标会随场景变化） |
| 端到端耗时 | 约 6~10 s |
| 运行模式 | 默认完整模式（`--quick` 为快速模式：单一样区、缩短遥测） |

```bash
node src/cli.mjs        # 生成 data/run_report.txt + data/run_result.json
node src/selftest.mjs   # 103 项断言，期望输出「103 项通过, 0 项失败」
git diff data/          # 与入库产物对比，确认结果一致
```

## 3. 口径与边界（写简历、做汇报时必须遵守）

1. **全部为仿真结果**：地块几何、作物行、GNSS/IMU 观测、农田影像、CAN 报文均为合成数据。
   正确表述是「仿真验证 / 软件在环」，**不能**表述为「田间实测」或「装机验证」。
2. **数字绑定随机种子**：默认种子 20240501。换种子后指标会变化（±1~2 %），
   因此对外引用时须注明「种子 20240501、完整模式」。
3. **行内杂草召回低是方法边界**：行内召回 ≈ 0.11，行间 ≈ 0.71。单目 RGB 下颜色指数法无法区分行内杂草，
   如实记录该局限，而非调参把指标做高。
4. **调度与覆盖率的改善幅度依赖场景规模**：10 地块 / 4 机具。地块数、机群规模变化时，改进百分比不具可比性。
5. **未实现部分不可暗示已实现**：Stanley / LQR / MPC 控制器、LiDAR 点云、深度学习杂草模型、
   真实 CAN 硬件驱动与云端微服务部署，均只在文档中作为设计或文献量级讨论，代码中不存在。

## 4. 产物为什么入库

`data/run_report.txt` 与 `data/run_result.json`（约 400 KiB）是**入库的**：

- 它们是本仓库结论的原始凭证，评审者无需运行即可核对；
- 文本报告可 `diff`，便于发现「代码改了但报告没更新」的漂移；
- `run_result.json` 供下游程序直接消费（地块几何、路径采样、调度甘特、跟踪曲线、识别统计、融合精度、报警明细）。

重新运行会覆盖这两个文件；若只是想验证，请先 `git stash` 或复制一份再对比。
